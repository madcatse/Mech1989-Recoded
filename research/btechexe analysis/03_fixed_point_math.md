# 3. Координаты и fixed-point математика

## Вывод

Движок активно использует 16-битные значения, 32-битные произведения и сдвиги на 15 бит. Это соответствует fixed-point арифметике, близкой к Q15, хотя в разных подсистемах могут применяться разные масштабы.

Характерный шаблон:

```c
result = (a * b) >> 15;
```

Углы представлены циклическими 16-битными величинами. Константы `0x80`, `0x140`, `0x400`, `0xb40`, `0x1c40` похожи на угловые шаги, ограничения скорости вращения или диапазоны прицеливания.

## Рекомендация

В современном движке:

- мировые координаты хранить в `double` или `float`;
- углы — в радианах;
- оригинальные величины загружать через слой преобразования;
- не терять исходные integer-параметры, чтобы можно было сравнивать с оригиналом.

```cpp
struct LegacyUnits {
    static float angleToRadians(std::int16_t value);
    static float distanceToMeters(std::int32_t value);
    static float speedToMetersPerSecond(std::int16_t value);
};
```

## Что нужно измерить динамически

1. сколько legacy-единиц соответствует полному обороту;
2. масштаб мировых координат;
3. частота симуляционных тиков;
4. формат скорости;
5. масштаб высоты terrain;
6. коэффициенты проекции камеры.

## Проверка

В DOS-версии следует записать состояние до и после:

- полного разворота;
- движения на один тайл;
- одного шага ускорения;
- поворота торса на визуально измеримый угол.

## Уверенность

**Высокая** для наличия fixed-point математики.  
**Средняя/низкая** для точных коэффициентов единиц.
