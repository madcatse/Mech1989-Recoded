# 2. Ограничения и модель боевых объектов

## Вывод

В BTECH.EXE регулярно встречаются циклы по восьми элементам. Это указывает на фиксированный пул до восьми основных участников боя.

Рядом используются таблицы с характерными шагами:

- около `0x0e` байт на короткий слот;
- около `0x55` байт на расширенное состояние;
- парные таблицы расстояний и признаков видимости.

## Вероятная организация

```cpp
struct CombatantSlot {
    MechRuntime* mech;
    WorldObject* worldObject;
    uint16_t team;
    uint16_t state;
};
```

Дополнительно:

```cpp
Distance distance[8][8];
bool visible[8][8];
```

Матрицы симметричны и вычисляются один раз на тик, после чего используются AI, радаром и оружием.

## Практическая ценность

Такая схема уменьшает число повторных вычислений:

- расстояние между двумя объектами;
- проверка линии видимости;
- принадлежность к команде;
- доступность цели;
- нахождение ближайшего противника.

## Реализация в новом движке

Жёсткое ограничение в восемь объектов сохранять не обязательно. Следует оставить API, поддерживающий произвольное количество `Combatant`, а матрицы заменить кэшем пространственных запросов или компактным adjacency-контейнером.

Для режима строгой совместимости можно ввести:

```cpp
constexpr std::size_t LegacyMaxCombatants = 8;
```

## Уверенность

**Высокая** для ограничения восьми основных участников.  
**Средняя** для полного состава полей короткого и расширенного слота.
