# 1. Архитектура боевого цикла

## Вывод

`FUN_1000_000d` с высокой вероятностью является главным циклом боевого режима. Она выполняет инициализацию, затем бесконечно обновляет ввод, пространственные отношения, механику боя, AI, временные объекты, рендер и состояние миссии.

## Наблюдаемый порядок подсистем

```text
опрос таймера и ввода
→ пространственные отношения
→ cooldown и тепло
→ управление игроком
→ AI
→ снаряды и эффекты
→ повреждения и уничтожение
→ построение кадра
→ проверка завершения боя
→ увеличение счётчика тиков
```

Особенно важно, что порядок обновлений устойчив. Он влияет на то, использует ли AI координаты текущего или предыдущего тика, когда уменьшается cooldown и в какой момент регистрируется попадание.

## Практическая интерпретация

Для нового движка следует использовать фиксированный шаг симуляции:

```cpp
void BattleSimulation::fixedTick(float fixedDt) {
    updateInputCommands();
    updateSpatialRelations();
    updateCooldownsAndHeat();
    updatePlayer();
    updateAI();
    updateProjectiles();
    resolveCollisions();
    resolveDamage();
    updateAnimations();
    updateMissionState();
}
```

Рендер должен работать независимо и интерполировать состояние между двумя симуляционными тиками.

## Что переносить

- порядок подсистем;
- детерминированный fixed-step;
- раздельное состояние симуляции и изображения;
- единый счётчик боевого времени;
- отложенное создание и удаление объектов.

## Что не переносить буквально

- DOS-таймер;
- бесконечный цикл внутри платформенного слоя;
- непосредственную отрисовку из функции симуляции;
- глобальные адреса и монолитные таблицы.

## Уверенность

**Высокая** для назначения главного цикла.  
**Средняя** для точного назначения отдельных вызовов внутри него.
