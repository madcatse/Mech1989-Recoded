# 9. AI противников

## Вывод

AI организован как конечный автомат. Центральная функция проходит по участникам, кроме игрока, оценивает состояние меха и выбирает специализированное поведение.

В расширенном состоянии встречаются небольшие целочисленные режимы, что соответствует state machine.

## Вероятные состояния

- idle;
- acquire target;
- approach;
- attack;
- evade;
- retreat;
- disabled;
- scripted behavior.

Это рабочая классификация, а не окончательная расшифровка кодов.

## Данные, доступные AI

- расстояние до каждого участника;
- видимость;
- отношение команд;
- состояние цели;
- собственные повреждения;
- готовность оружия;
- направление и скорость;
- препятствия.

## Предлагаемая архитектура

```cpp
enum class AIBehavior {
    Idle,
    AcquireTarget,
    Approach,
    Attack,
    Evade,
    Retreat,
    Disabled
};

struct AIState {
    AIBehavior behavior;
    EntityId target;
    float decisionTimer;
    float desiredRange;
};
```

## Воспроизведение оригинала

Сначала нужно реализовать простой FSM, а не behavior tree. Это повысит вероятность совпадения поведения и облегчит сравнение.

## Задачи восстановления

1. соответствие числовых кодов состояниям;
2. алгоритм выбора цели;
3. желаемые дистанции;
4. приоритет оружия;
5. точность наведения;
6. время реакции;
7. обход препятствий;
8. условия отхода;
9. распределение целей между союзниками.

## Уверенность

**Высокая** для наличия FSM и централизованного AI update.  
**Средняя** для алгоритма выбора целей.  
**Низкая** для названий отдельных состояний.
